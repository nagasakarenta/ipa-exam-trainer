# 問題データの形式

`src/data/questions/*.json` は、次の形のオブジェクトの配列です（1ファイル = 1区分 × 1分野）。

```json
{
  "id": "ip-s-001",
  "exam": "ip",
  "section": "ip",
  "field": "strategy",
  "subfield": "企業と法務",
  "topic": "損益分岐点",
  "text": "問題文（本文）",
  "sub": "任意。表や前提条件など、問題文の下に等幅で表示する補足。改行は \\n",
  "code": "任意。擬似言語などのコード。改行は \\n",
  "choices": ["ア", "イ", "ウ", "エ"],
  "answer": 1,
  "explanation": "解説。正解の理由と、他の選択肢が誤りである理由"
}
```

| キー | 必須 | 内容 |
|---|---|---|
| id | ○ | 一意なID。`<exam>-<field頭文字>-<3桁連番>` |
| exam | ○ | `ip`（ITパスポート） / `fe`（基本情報技術者） |
| section | ○ | `ip` / `fe-a`（科目A） / `fe-b`（科目B） |
| field | ○ | `strategy` / `management` / `technology`（科目Aまで） / `algorithm` / `security`（科目B） |
| subfield | ○ | シラバスの中分類（例：企業と法務、経営戦略、システム戦略、開発技術、プロジェクトマネジメント、サービスマネジメント、基礎理論、コンピュータシステム、技術要素） |
| topic | ○ | 論点の短い名前（10文字程度） |
| text | ○ | 問題文 |
| sub | – | 補足（表・条件など） |
| code | – | 擬似言語コード |
| choices | ○ | 選択肢。4つ以上 |
| answer | ○ | 正解の添字（0始まり） |
| explanation | ○ | 解説 |

## 書き方の約束

- 問題はすべてオリジナルで書く（IPA の過去問を写さない）
- 事実は確実なものだけを使う。法令名・規格名は現行のもの
- 正解は選択肢の中で一意に決まるようにする。正解の位置（0〜3）は偏らせない
- 解説は「なぜ正解か」と「他の選択肢はなぜ違うか」を両方書く
- 文中に `</script>` を含めない
