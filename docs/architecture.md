# 設計メモ

## 全体像

```
ブラウザ（React SPA）
 ├─ data/        問題集（JSON）と試験の仕様（分野比率・合格基準）
 ├─ lib/         純粋なロジック。UI に依存しない
 │   ├─ srs      間隔反復（復習日の決定）
 │   ├─ mock     本試験の比率に合わせた模試の問題選び
 │   ├─ scoring  採点・合否判定・1000点換算
 │   ├─ stats    分野・論点別の集計、日別の記録、連続学習日数
 │   ├─ random   再現できる乱数（テスト用）とシャッフル
 │   └─ storage  localStorage への保存・復元・取り込み時の検証
 ├─ state/       useReducer による学習データの状態管理（reducer は純粋関数）
 ├─ components/  出題エンジン（Quiz）・結果表示（Results）・共通レイアウト
 └─ pages/       ホーム / 分野別ドリル / 模擬試験 / 復習 / 学習記録 / 設定
```

サーバは持たない。学習データはブラウザの `localStorage` に保存し、JSON で書き出し・読み込みできる。
GitHub Pages に静的ファイルとして配信する（サブパスでも動くように `base: "./"` と HashRouter を使う）。

## 判断とその理由

### ロジックを `lib/` に切り出し、React に依存させない

採点・間隔反復・模試の構成はアプリの核心で、間違うと学習の判断を誤らせる。
UI から切り離した純粋関数にしておくと、Vitest で入力と出力だけを見るテストが書ける。
乱数を使う処理（模試の問題選び、シャッフル）は乱数生成器を引数で受け取り、テストでは種を固定して再現できるようにした。

### 間隔反復は SM-2 を単純化

Anki などで使われる SM-2 を、4段階の自己評価なしの「正解／不正解」だけで回るように単純化した。

- 正解：間隔を 1日 → 3日 → 7日 → それ以降は `ease` 倍に伸ばす。`ease` は +0.05（上限 3.0）
- 不正解：間隔を 0 に戻し、同じ日のうちにもう一度出す。`ease` は −0.2（下限 1.3）
- 間隔 7 日以上を「定着」と見なす

四択問題は「なんとなく当たる」ことがあるので、自己評価を増やすより、不正解を厳しく扱う方が実態に合うと判断した。

### 模試は本試験の分野比率で按分する

ITパスポートはストラテジ 35・マネジメント 20・テクノロジ 45、基本情報 科目A は 41・7・12、科目B は 16・4。
問題数を減らしたときも比率を保ち、端数は比率の大きい分野から配る。ある分野の問題が足りないときは、その分野はあるだけ出し、残りを他の分野で補って重複は出さない。
制限時間も本試験と同じペース（1問あたりの時間）で按分する。

### 採点は正答率からの簡易換算と明記

本試験は IRT（項目応答理論）で評価点を出すため、正答率を 1000 倍した値は目安にしかならない。
画面では必ず「簡易換算」と書き、ITパスポートの分野別基準（各分野 300 点）も再現して、合否ラインの判定に使う。

### 学習データの保存は `version` 付き、取り込み時は検証する

`localStorage` の JSON は壊れていることも、別のバージョンのものであることもある。
読み込みに失敗しても画面が壊れないように空の状態で始め、ファイルからの取り込みは `normalize` で形を検証・補完する。

### 問題データは JSON で、形式をテストで強制する

問題を追加するときに最も起きやすいミスは「正解の添字がずれている」「選択肢が空」「ID が重複」。
`src/data/questions.test.ts` が全問に対して形式を検証し、CI で落とす。
正解の位置が偏ると「ウが多い」と覚えてしまうため、ITパスポートの問題は正解位置の分布もテストで確認している。

## 既知の制約と今後

- 問題集はバンドルに同梱している（約 500KB）。問題数が増えたら区分ごとに動的 import に分ける
- 推定点は簡易換算。過去の受験結果を集めて回帰で補正する余地がある
- 端末間の同期はない（JSON の書き出し・読み込みで代替）
- 科目B はトレース問題が中心。擬似言語を実際に動かす簡易インタプリタがあると学習効果が高い
